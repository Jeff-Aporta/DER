# Tiquetes (tks)

El tablero que toda app puede montar sin conditionally nada: tiquetes numerados, con contenido, propósito, pendientes,
columna del kanban, regla de cierre, autor y asignación. El mismo plugin sirve para que una persona diligencie tickets
a mano o para que un agente los tome y los resuelva.

## Entidad `tks` (tabla `tks_tks`)

| Columna | Tipo | Qué es |
|---|---|---|
| `itk` | string pk (secuencia) | el número del tiquete: base 36 en mayúsculas con relleno a 6 dígitos (`000001`, `000002`… `00000A`, `000010`) |
| `requerimiento` | text | el contenido del requerimiento (html\|md) |
| `proposito` | string 300 | la idea resumida: el foco del tiquete |
| `jtodo` | json | los pendientes: `[{ hecho, contenido, jedit: { fh, iusuario } }]` |
| `estado` | string 40 | la columna del tablero (`POR_HACER` por defecto; es texto libre: cada empresa usa las suyas) |
| `bfinalizado` | bool | la regla de cierre del tiquete |
| `fhcre` | datetime | desde cuándo está abierto |
| `bactivo` | bool | baja lógica (archivar; nunca se borra) |
| `iusuario` | string 120 | quién lo creó |
| `jasignados` | json | `{ usuarios: [], roles: [], grupos: [] }` |
| `qtotalmensajes` | virtual | cuántos mensajes tiene el tiquete |
| `qcalificacion` | virtual | la calificación promedio |

Las columnas virtuales se encienden en `seed` si el consumidor instaló los plugins de mensajes y de calificaciones: un
plugin no depende de otro.

## Reglas

- **El alta pone los defaults**: `fhcre` (ahora), `iusuario` (la sesión), `estado` (`POR_HACER`) y `bfinalizado` (la regla).
- **La numeración es texto**: `itk` lo quema una secuencia en base 36, en mayúsculas, con relleno de ceros a 6 dígitos
  (`000001`, `000002`, … `00000A`, `000010`). Así el número admite letras, el relleno es de ancho fijo (un simple sort
  ordena por número) y cada empresa puede adaptarlo con su controller (otra base, otro relleno o un prefijo).
- **El estado es un texto libre (STR)**: el plugin trae `POR_HACER` por defecto y la regla de cierre compara sin
  distinguir mayúsculas, así que cada empresa puede escribir sus columnas como quiera.
- **La regla de cierre**: `cfg.estadosFinalizados` declara qué estados cierran un tiquete. Con esa lista, `bfinalizado` lo
  manda el estado y el valor manual no cuenta; sin lista, el usuario puede marcarlo a mano
  (`cfg.permitirFinalizadoManual`, por defecto true).
- **La baja es lógica**: `DELETE` archiva (`bactivo` false) y la fila nunca se borra.
- **La asignación decide quién ve qué**: `jasignados` con usuarios, roles y grupos; `*` en grupos significa "todos".
  Sin asignación, solo quien lo creó lo ve.
- **La coherencia la mantiene el sistema**: las referencias (`jasignados`, `iusuario`) son definiciones abiertas, sin FK.

## Rutas

| Ruta | Seguridad | Qué hace |
|---|---|---|
| `POST tk` | sesión | crea el tiquete (el `POST` va al singular) |
| `GET/PUT/DELETE tk/{itk}` | sesión | lee, cambia y archiva el tiquete |
| `GET tks` · `GET tks?q=` | sesión | lista y consulta (filtros y paginación de DER) |
| `POST tks/crear` | sesión | crea con los defaults del servidor |
| `GET tks/mis` | sesión | los tiquetes que la sesión ve (`page`, `pageSize`, `estado`, `q`); responde `{ tks, total }` |

## Montar

```ts
const tks = createServer(tksServer, { db, cfg: { estadosFinalizados: ["finalizado"] } });
const router = createRouter(ctrls, { basePath: "/api", plugins: [tks] });
await router.seed();
```

Cliente:

```ts
const tks = createClient(tksPlugin, { baseUrl: "/api", headers: auth.headers });
const fila = await tks.crearTk({ requerimiento: "#42", proposito: "Arreglar el login" });
const mios = await tks.misTks();
```
