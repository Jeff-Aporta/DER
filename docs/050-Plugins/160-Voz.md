# Voz (notas de voz)

> Skill: [voz.md](https://cdn.jsdelivr.net/gh/Jeff-Aporta/DER@main/skills/voz.md) · temario: [README.md](https://cdn.jsdelivr.net/gh/Jeff-Aporta/DER@main/skills/README.md)

La voz con la que habla cada app y la sintesis de las notas de voz.

## Por que es un transversal

La voz es **parte de la configuracion de la app**, no un parametro de cada mensaje. Por eso:

- se cambia en cualquier momento (panel de administracion) y **todos los bots** (WhatsApp, Telegram, el CRM) usan la misma;
- el motor de sintesis lo pone el consumidor: DER no conoce ningun TTS;
- el audio guardado caduca a los 30 dias (`vidaDias`) para poder escucharlo despues en el CRM.

## La tabla

`voz_app` (iapp, motor, voz, perfil, idioma, tono, activa)

| columna | que es |
|---|---|
| `iapp` | que app habla asi (`chat-assistant`, `crm`...) |
| `motor` | `qwen`, `edge`, `kokoro` u `otro` |
| `voz` | la clave de la voz (`aiden`, `serena`) |
| `perfil` | `rapido` (en vivo, sin tono) o `video` (con tono) |
| `idioma`, `tono` | pistas para el motor |
| `activa` | con `false` la app responde solo por texto |

## El contrato del motor

```ts
type MotorVoz = {
  sintetizar(p: { texto: string; voz: string; perfil: "rapido" | "video"; idioma: string; tono?: string }): Promise<Uint8Array>;
  voces?(): Promise<{ clave: string; nombre: string; genero?: string }[]>;
};
```

El consumidor tambien puede dar `guardar`: el audio se guarda con su origen (`origin` + `idorigin`) para poder escucharlo.

## Los verbos

```ts
await voz.configDe("chat-assistant");
await voz.configurar("chat-assistant", { voz: "serena", perfil: "rapido" });
const a = await voz.sintetizar({ texto: "Listo", iapp: "chat-assistant" });
```

## Rutas

- `GET /api/voz/config?iapp=`
- `POST /api/voz/config`
- `GET /api/voz/voces`
- `POST /api/voz/sintetizar` (devuelve el audio binario)
